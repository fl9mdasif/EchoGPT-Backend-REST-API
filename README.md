# EchoGPT Backend

Backend REST API for the EchoGPT Chrome Extension — built with NestJS,
PostgreSQL, Prisma, and Swagger for the AppifyDevs backend internship
assignment.

Planning docs: [`docs/prd.md`](docs/prd.md) ·
[`docs/architechture.md`](docs/architechture.md) ·
[`docs/tasks.md`](docs/tasks.md) · [`docs/rules.md`](docs/rules.md) ·
[`docs/memory.md`](docs/memory.md)

The application itself lives in [`server/`](server).

## Quick start

```bash
cd server
cp .env.example .env        # fill in real secrets for local dev
npm install --legacy-peer-deps
docker compose up -d db     # Postgres on localhost:5432
npx prisma migrate dev      # apply schema once one exists (Phase 2+)
npm run start:dev           # http://localhost:3000/api/v1
```

Swagger UI: http://localhost:3000/api/docs

### Run everything in Docker (api + db)

```bash
cd server
docker compose up -d --build
```

## Why `--legacy-peer-deps`

This scaffold was generated by a very recent `@nestjs/cli` release pulling in
Vitest 4 / TypeScript 6 / Prisma 7. npm 11's dependency resolver
(`arborist`) currently crashes on part of that peer-dependency graph
(`Cannot read properties of null (reading 'edgesOut')`) — a known npm bug,
not a problem with this project's own dependencies. `--legacy-peer-deps`
sidesteps it; see `docs/memory.md` for the note.
